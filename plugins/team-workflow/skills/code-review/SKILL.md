# Skill: code-review

## Review Areas
- Readability
- Naming
- SOLID
- DRY
- KISS
- Testability
- Security
- Error handling
- Validation
- Logging
- Documentation
- Architecture boundaries
- Stack best practices and anti-patterns (see the stack conventions skill, e.g. `dotnet-angular:stack-conventions`)
- Project rules and domain invariants (see `project-description.md`)

## Rules
- Do not add new features during code review.
- Only refactor or recommend fixes.
- Prefer simple improvements.
- Identify blockers separately from nice-to-have improvements.

## Output
1. Summary
2. Blockers
3. Important issues
4. Minor improvements
5. Suggested refactorings
6. Test gaps
7. Final recommendation
